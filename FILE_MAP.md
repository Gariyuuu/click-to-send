# FILE_MAP.md — Practical Map of Important Files

| Path | Purpose | When to edit | Edit risk |
|---|---|---|---|
| `index.html` | The entire page markup: 4 inputs (recipient, Discord IDs, message, passcode), 2 buttons, 1 status paragraph; links `style.css` and `script.js` | Adding/removing a form field, changing page title/favicon, adding a new button | Low — small, self-contained; but any new input needs matching JS wiring in `script.js` |
| `style.css` | All visual styling — single dark card layout, no framework | Changing colors, spacing, layout, adding styles for a new element | Low — isolated, no build step, changes are visible immediately |
| `script.js` | All client-side logic: reads form inputs, does light client-side validation, `fetch`s `/api/send-email` and `/api/send-discord`, writes results to the status line | Adding a new button/action, changing client-side validation, changing how results are displayed | Medium — must stay in sync with whatever shape `api/*.js` actually returns; a mismatch breaks the status text silently (no crash, just wrong/blank message) |
| `api/send-email.js` | Vercel serverless function: validates passcode + input, sends one email via Gmail SMTP (`nodemailer`) | Changing email validation, changing the email subject/body, adding CC/BCC, changing SMTP provider | **High** — this is a security/abuse boundary (passcode check) and a real external-send path; a mistake here can send unintended emails or weaken the passcode gate. Review carefully. |
| `api/send-discord.js` | Vercel serverless function: validates passcode + input, DMs up to 20 Discord user IDs via the Discord REST API | Changing the recipient cap, changing ID validation, changing the DM content format | **High** — same reasoning as `send-email.js`: passcode gate + real external-send path. |
| `package.json` | Project metadata, `"type":"module"`, the one dependency (`nodemailer`), empty `"scripts"` | Adding a dependency, adding a script (build/lint/test) | Low-Medium — adding a script changes what `CLAUDE.md`/`TESTING.md` should say is runnable; keep those in sync |
| `package-lock.json` | npm lockfile pinning `nodemailer@9.0.3` | Regenerated automatically by `npm install`; don't hand-edit | Low, but don't hand-edit |
| `.env.example` | Template listing all 4 env vars (`SITE_PASSCODE`, `GMAIL_USER`, `GMAIL_APP_PASSWORD`, `DISCORD_BOT_TOKEN`) with placeholder values | Adding/removing/renaming an env var used by `api/*.js` | Medium — must stay a placeholder-only file; never write a real value here |
| `.gitignore` | Ignores `node_modules`, `.env*`, `.vercel`, logs, editor files | Adding a new kind of generated/local file to ignore | Low |
| `.vercel/project.json` | Links this repo to Vercel project `click-to-send` (`projectId`, `orgId`) | Never hand-edit; regenerated by `npx vercel link` | High if broken — deploys would target the wrong project or fail; don't touch manually |
| `README.md` | Human-facing setup guide: install, pick a passcode, Gmail app password, Discord bot setup, env vars, local dev, deploy | Update when setup steps actually change | Low — documentation only, but keep accurate since this memory system defers to it for the human-facing quickstart |
| `node_modules/` | Installed dependency (`nodemailer` only) | Never hand-edit; regenerate via `npm install` | N/A (gitignored) |

## Where to make common changes

- **Add a new API route:** create `api/<name>.js` exporting a default
  `(req, res) => {...}` handler (Vercel's filesystem routing picks it up
  automatically as `POST /api/<name>` — no routing config needed). Follow
  the existing pattern in `api/send-email.js`/`api/send-discord.js`:
  method check → env-var-configured check → passcode check → input
  validation → the actual external call inside `try/catch` → JSON
  response. Add any new required env var to `.env.example` and to
  `CLAUDE.md`'s environment table.
- **Change the form (add/remove/rename a field):** edit the `<input>`/
  `<textarea>` in `index.html`, then update the matching
  `document.getElementById(...)` reference and click-handler logic in
  `script.js`. If the field is sent to an API route, update that route's
  input validation in `api/*.js` to match.
- **Change styling:** edit `style.css` directly — it's the only stylesheet,
  no preprocessor/build step, changes take effect on page refresh.
- **Add an env var:** (1) read it via `process.env.<NAME>` in the relevant
  `api/*.js` handler, following the existing "missing → 500" pattern; (2)
  add a placeholder line to `.env.example`; (3) add a row to `CLAUDE.md`'s
  environment table; (4) if deploying, add the real value in the Vercel
  dashboard (Project → Settings → Environment Variables) — `.env`/
  `.env.local` are not uploaded automatically (per `README.md`).
- **Change deploy config:** there is no `vercel.json` in this repo (Vercel
  auto-detects a static site + `api/` functions with zero config). If one
  is ever added, document it in `DEPLOYMENT.md`. `.vercel/project.json`
  should not be hand-edited — it's CLI-managed link metadata.
